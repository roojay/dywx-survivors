## 接手顺序

1. 先读 `REQUIREMENTS-COVERAGE-FINAL.md`，区分已实现、离线覆盖、实机未验证、建议调优与明确后延。
2. 模块说明：`CAMPAIGN.md`、`ECONOMY.md`、`ARENA.md`、`CONTENT-CONFIGURATION.md`、`SAVE.md`。
3. 跑 `bash scripts/test-full-game-all.sh --sanitize`。最终结论只能用于同一套冻结源码，脚本在结束时检查源哈希；并发修改期间的编译可能混合ABI，不可作为最终证据。
4. 读 `NATURAL-PLAY-CHECK.md`。不注入战力的固定样例既有成功也有失败；御兽Boss节奏、新号与传统/无尽平衡仍需专项人工验证。
5. 获得UE环境后运行仓库 Windows 包装脚本，保留UHT/UBT、资源bootstrap、Cook/Package日志。修复真实编译错误，而不是依靠字符串契约测试推断可编译。
6. 完整试玩新号→层2→层3；每个经济动作、全部可用融合、失焦后恢复、传统/无尽保存并离开、切换修士、续档一次性消费、无尽5/10波洞主与结算各验证。
7. 核对720p/1080p/110%字号、异象和Boss预警、悬停双列、100+敌人、前后台GPU/FPS，以及真实磁盘失败/断电行为。
