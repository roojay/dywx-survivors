## 范围与基线

用户要求 Windows 离线期间先在 dot 继续检查测试。恢复的完整基线为 `19e00a2602a35487a160f3a039c3f426014a1fb3`。恢复 bundle 的大小、SHA256、Git prerequisites 和 Library 文件身份验证通过；基线冻结副本全量 ASan/UBSan 门禁通过，日志见 `baseline-sanitizer.log`。

基线门禁通过并不代表没有缺陷。本轮另行编写边界回归并进行交叉审查，实际复现以下问题。

## 修复

1. 赤山/青岚洞主第二阶段召唤未预留洞主重新加入列表的位置，突破敌人上限。现保留一个位置；三洞天、多种容量和非满员召唤数均验证。
2. 回旋飞剑穿透耗尽不立即返程，且返程仍追踪出程目标。现耗尽进入返程并关闭出程追踪，保持既定伤害数值。
3. 水弹灭火检测使用上一帧运动段，最后一段可能遗漏。检测移至本帧位移之后。
4. 非有限 fixedStep 可令模拟冻结。现回退默认步长。
5. 经济恢复接受错误炼化撤销金额，导致返还物品但保留收益。现复算金额，并验证锁定状态、法宝 ID 高水位与交易生命周期；拒绝操作保持原状态及随机序列。
6. 存档接受不一致的整理序号，恢复后下次整理无法开启经济。现要求序号一致且未耗尽。
7. 商店 token 耗尽前拒绝生成，避免回绕。独立交叉审查纠正了最初统一预留五件的过度拒绝：最终按实际快速/传统商品数量预留。
8. Economy 弹层进入 UIOnly 时未清除游戏输入。抽取入口清理函数，避免清理发生在逐帧 tick。这里只能证实源码缺口和契约测试；实际键盘残留行为尚未在 UE 复现。

新增 `test-combat-boundaries.sh`、`test-save-economy-boundaries.sh` 并纳入总门禁。战斗新增回归在原 Simulation 上有 10 个失败断言，修复后通过。经济/存档测试包括合法的三层级、两模式、三轮整理 Export/Restore 矩阵，避免只测试拒绝坏输入。

未调整生产伤害、生命、冷却或掉落概率来让自动策略通关。

## 自然玩法证据

基线重复结果及合法策略诊断见 `BASELINE-NATURAL-DIAGNOSIS.md`；不能和修复后的版本混用。

修复版保持原十例及原策略，结果是 **3 胜、4 死、3 个观察上限**，基线为 2 胜、6 死、2 个上限。剑修传统 seed29 由第九波死亡变为 2154.93 秒完成第十波，剑修无尽到达 1200 秒观察上限；不是证明无尽通关。新号体修仍在 215.791 秒第二波死亡，御兽快速仍到 1200 秒上限。

普通与 ASan/UBSan 的 CSV、trace 和源码清单逐字节一致。证据见 `natural-fixed/`。最终商店 token 数量校正后再次冻结源码，串行运行完整 sanitizer 门禁与普通/ASan/UBSan 自然样例，均 exit 0，三份自然证据逐字节一致；结果保持 3 胜、4 死、3 上限。完整门禁见 `final-sanitizer.log`。

- 御兽时长与新号难度还需验证和调优；基线探索说明策略有影响，不能推断所有难度问题都是策略导致。
