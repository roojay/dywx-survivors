## 已落地闭环

菜单 → 两位修士 → 火雷洞天快速模式 → 走位/遁术/自动术法 → 非暂停三选一与重悟 → 波末修为结算和法宝整理 → 迎战 → 两阶段流波夔君 → 胜利或陨落 → 重开。

规则以配套参数表为准：默认四波 100/120/140/160 秒；六波为配置变体；洞主两阶段 14000/16000 气血。十术法、五心法、两破境、十五法宝以及第一层系统已经有实际行为与测试，不仅是配置文字。

真实 UI 提供破境动作，避免只在自动测试里可调用；道典全部明示、未见灰色，发现后点亮。保底和发现记录跨局保存，但不保存本局战力或装备。炼化修为在调息内待结算可撤销，迎战时提交。详细默认决策见 IMPLEMENTATION-SCOPE.md。

## 重要测试证据

1. 独立测试覆盖移动、碰撞、遁术、预警、伤害、所有术法/等级、触发链、波次/洞主、成长/融合、装备与撤销、掉落与保底、重开和超限处理。大量断言是循环中的有限值/边界检查，不是同等数量独立场景。
2. ASan/UBSan 通过；LeakSanitizer 因宿主 ptrace 未运行。
3. 自动操作使用八方向移动/停步、真实候选/掉落/换装，不注入血量、修为或伤害。飞剑修士 seed 12 在 636.272 秒自然通关，洞主阶段 116.338 秒；近身修士有多个自然通关种子，洞主约 144–169 秒，仍长于参数表目标。
4. 固定源码/二进制重复回放一致，具体 SHA、命令和轨迹清单见 PLAYTHROUGH-CALIBRATION.md 及 playthrough-winning-trace.manifest.json。自动操作不等于真实人类反应、可见性或趣味验收。
5. 原型世界采用实例化模型、有限特效与角色数量预算。CPU 模拟测试不证明真实 GPU 流畅；60/15/5 预算需要运行时读回确认。

## 资源和视觉

三维场景不是整屏图片。人物、敌人、石坛、火柱和门楼具有实际网格，主角/群行妖魔有有限姿势网格步态。资源来自项目自制 Blender 几何、内置生图和指定的 Sarasa 官方字体；无付费 fal 调用或不明来源脚本。

实际模型仍是低模原型，未达到概念图细节；不是完整骨骼蒙皮动画。普通场景固定六处内部障碍，尚非完整的随机地块拼装。这些限制必须保留，不因测试通过删除。

参考视频按真实模拟轨迹离线渲染，持续带 NOT UE RUNTIME 标记。它帮助发现并修正友方火圈遮挡，不代表 UE 截图或性能证明。

## 恢复后的最小下一步

1. 在获授权且具备 UE 5.8 的环境取得当前完整提交，核对字体、scene.json、音频源和脚本。
2. 跑离线汇总检查，再执行 package-windows.ps1，修复真正编译/资源错误并保留日志；不要绕过 bootstrap 门禁。
3. 启动独立包，不只 PIE：检查主菜单文字、两角色、开始、三选一/重悟/破境、调息装备操作、暂停/失焦/最小化/恢复、胜败/重开、再次启动的道典/保底。
4. 用实际硬件测 720p/1080p、100%/110% 字号、前后台 FPS/GPU、130 妖魔与密集特效。录制完整操作场景并与概念图对照。
5. 至少试玩两角色各一局，再调整初始参数。只有这个阶段通过，才把版本标为“可交付试玩”。

不要为了满足早晨目标把离线预览改称实机，不要用旧 EXE 冒充新版本，也不要将浏览器替代品当作 UE MVP。
