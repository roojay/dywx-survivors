# 最小可玩 MVP 实施口径

2026-10-30 夜间用户授权：继续按游戏玩法设计及参数配置表实现最小可玩 MVP，并行迭代。此文是本次实施的默认决策记录，不把未执行的 UE 构建或体验测试写成完成。

## 基线

- 以 `docs/gameplay-design-v0.1.md` 和 `docs/mvp-prototype-config-v0.1.md` 这对文档为依据。
- 用户本次明确指向玩法设计及参数配置，故不再把早期“三波、三技能、两遗珍”方案当作当前实现基线。
- 参数表中原型范围优先于完整设计的后续系统：快速模式、1 洞天、2 修士、10 术法、5 心法、2 破境、15 法宝。
- 默认 4 波（100/120/140/160 秒）后两阶段洞主；6 波为配置变体。不能将测试用短时长作为正式默认值。
- 保留 UE5 原生实现。无浏览器游戏替代，无付费模型调用，无额外账号/凭据创建。

## 明确的最小闭环

主菜单 → 修士 → 洞天快速模式 → 走位/遁术/自动施法 → 修为与三选一 → 波间调息、装备整理 → 下一波 → 洞主 → 胜利或陨落 → 直接重开。

静态 HUD 预览不得冒充战斗。生命、经验、敌人、伤害、掉落、冷却和结算必须由同一个实际模拟驱动；场景实体与预警跟随模拟，不由录制视频播放。

## 暂定实现决策

1. 形态轴共鸣按参数表 §12 默认开启，但可配置关闭。元素共鸣始终按第一层开启。
2. 专属心法占用 4 个心法槽之一；不会额外叠出第 5 槽。
3. 按 2026-10-31 用户最新要求，妖潮内的顿悟选择自动暂停战斗与视觉时间，全部候选处理完才恢复；手动/失焦暂停独立保留。用紧凑三选一及 1/2/3 快捷键。经验可排队，不能因多个顿悟同时触发而丢失。
4. 炼化修为在本次调息内标记为待结算，可撤销；点击迎战时提交，避免撤销涉及已经选择的升级。相关待选升级须安全保留，UI 明示未结算状态。
5. 首个修士使用断岳行者名称，但实际起手术法改为参数表的焚心掌；第二位暂用巡星羽客名称，起手赤焰飞剑。旧 UI 的断岳三叠/回风刃环/穿云重矢仅属旧概念，不沿用为此版本数值。
6. 暂不启用灵石、坊市、封存/跳过、异象、重铸、宝匣、劫数、无尽。传统/无尽在 UI 明示后续内容，不能进入空实现。
7. 轻量程序化/社区许可明确的资源可作为美术占位，必须与原图愿景区分，不宣称模型、动画已达到概念图质量。

## 实现与证据分层

- 纯 C++20 模拟：在 dot 真实编译，做规则、状态转换、确定性、边界、内存及长局测试。
- UE 适配：实际 C++ 场景、输入、相机、实例化实体和原生 UI；依赖引擎部分在 dot 没有 UE 的条件下只能审查，不能伪造编译通过。
- 资源：保留 Blender 源文件、可复现脚本、导出校验与预览。Blender 渲染不等于 UE 渲染。
- 后续 UE 验收：真正编译、启动、全流程截图/录屏、帧率及 GPU 测量；需要可用且获授权的引擎环境。

当前设备事实：用户 Windows 已关机，dot 无 UE/可用 GPU。今晚尽可能完成实现和可执行的离线验证；不能承诺未实测的“流畅精美”或 Windows EXE。
